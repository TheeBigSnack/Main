## 0.5.0 (2026-09-28, toward a sellable product)

Ten tasks were chosen for the three months to a sellable product (PLAN.md M4 to M6). This release carries the first of them; every piece runs against sample data or a mock until the owner creates the accounts.

Added
- **CI** (`.github/workflows/ci.yml`): the unit tests, each e2e flow in its own Ubuntu job with Playwright's Chromium, and the packed zip as an artifact, on every push. The flows now run one at a time by default through `scripts/e2e-all.mjs` (`npm run test:e2e:parallel` for two at a time) in unique temp folders.
- **Terms and Privacy in the wizard**: a step after the posting rules with the two documents and an acceptance the synced profile keeps with its edition (`settings.legal`, `src/legalLinks.js`); Settings shows it and has the same tick. Until the documents are published (the addresses are placeholders today) the step is informational and records nothing: nobody is asked to accept what they cannot read.
- **Chrome Web Store listing draft** (`store/listing.md`): summary equal to the manifest's description (a test keeps it so), the long description, the permission justifications, the screenshot plan, the submission checklist.
- **The adapter contract is complete** (`extension/adapters/README.md`): a platform is one module with `probeInPage`, `searchInPage`, `detect`, `origins`, `scanOptions`, `scan`, `getDetails`, `normalize`, `makeDirectSearch` and `photoOrigins`; `src/scan.js` keeps only the neutral site probe; the Dealer Inspire normaliser lives under `adapters/`; the service object is opaque outside its adapter; photo hosts are recorded per website (never requested); contract tests run every adapter against the mock site in a sandbox and the guard tests forbid any adapter that acts on a page.
- **Manager view** (`manager/`): the Milestone 4 page over Supabase with magic-link sign-in and a sample-data mode, posts per salesperson, sold cars still listed with hours open, price changes not yet updated, a CSV with the pilot's definitions.
- **Landing page** (`site/`): mobile-first, pricing from `marketing/pricing.json`, an honest FAQ, a demo request form with a configurable endpoint and a mail fallback; its own honesty test. A "See it" section shows five product images taken from the sandbox with sample data (`npm run screenshots` regenerates them into `site/screenshots/`; the Web Store gets real ones from the owner, `store/listing.md`).
- **Accounts foundation** (`supabase/`): the schema (dealerships, memberships, listings, to-do items, scan summaries, post attempts, rewrite usage, invites) with row-level security per dealership and a plain-SQL test that dealership A cannot read B; Edge Functions `rewrite` (auth, per-user rate limit, monthly cost cap, the same prompt and guardrails as `backend/`) and `sync` (the posted registry and pilot numbers converge across machines); `extension/src/account.js` (magic-link and code sign-in, sessions in local storage only) and `extension/src/sync.js` (pure merge of registries and flags, tested with two machines converging). Stripe is reached over `fetch`; the secret key lives only in the function's secrets. Nothing is switched on until the owner creates the Stripe objects the README lists; the manager page does not show it yet.
- **Billing in the product**: the manager view has a Billing card (no plan yet / free pilot with days left / subscribed / lapsed) with Start the free pilot, Subscribe and Manage billing for managers, each calling the billing function; the sync answer carries the dealership's plan, Settings' Account line shows it, and the sync and rewrite functions answer 402 for a lapsed dealership (salespeople can still post by hand; nothing syncs and no draft is written until a manager renews).

- **Wizard Price step**: the price to post (the lower second price only when the website shows one) and the price note, suggested and never filled in, now have their own set-up step between the address and the permission.
- **Store-install onboarding** (`marketing/onboarding-store.md`): the manager's email, each salesperson's install-and-sign-in email and the day-7 check-in, all generic; the pilot agreement and Schedule A of the subscription agreement are blank tables that name the pricing config instead of a dealer.

## 0.4.0 (2026-09-28, Milestone 3 started)

Changed, for any dealer (2026-09-28, after an audit for wider use: 44 findings, 43 confirmed; 21 fixed here, the rest scheduled in PLAN.md)
- **The synced profile carries the person, not the dealership.** On another dealership's website only your name, role, listing defaults and rewrite-service address come along; that website's name, address, stores, price basis, price note and daily cap apply (`settings.js` `settingsFromProfile`, `scanRunner.js` `performScan`). Before, a Waynesburg profile signed every description on a sister store's site with the wrong dealership.
- **The price note is suggested, never filled in.** A first scan no longer writes "Price includes the $490 doc fee" into every description; Settings shows the suggestion from the website's price gap and a person decides whether it is true for the store. Installs from before keep the note they had; a new machine starts with none until it is typed (PILOT.md and the day-0 email say so). A note whose fee amount does not match a car's two-price gap is flagged for that car (`rewriteTemplate.js`, guardrail `price-note-amount`), and the note is left out of a car that had to be posted at the main price under the "lower second price" basis.
- **"Price before fees" only when the website shows one.** The radio appears only on a website with a consistent lower second price, with a note that some states require fees inside the advertised price; a car without such a price is posted at the main price, never at a number that is not on the website (`rescan.js` `basisPrice`, the panel's car card says which applied).
- **The side panel no longer writes stale copies back.** "It's posted", "Saved as draft" and the queue re-read storage before writing, so a car marked posted or taken down in the popup while another car was on the form stays that way, and a queue stopped from the popup stays stopped.
- **The test hook is fenced.** `devOverrides` can move addresses and timings only (`formMap.js` `DEV_OVERRIDE_KEYS`, `applyOverrides`); the fields, their options and `neverFill` are always the frozen map's. A guard test checks it.
- **A non-English Facebook is named.** The fill and the dry run report the page language; when nothing is found on a page that is not in English, the panel says so and how to switch, instead of asking for a report.
- **Blocked posts record a reason code**, not the message text, in the pilot numbers.
- **Packaging**: `npm run pack` writes `dist/lot-sync-extension-<version>.zip` from `extension/` alone (no dependencies; refuses when the manifest and package versions differ). README gained an Update section; the popup's Settings and the dry-run report show the build. `test/manifest.test.js` keeps the description within the Web Store's 132 characters, the version equal in three places, and every permission named in `legal/chrome-web-store-privacy.md`.
- **The rewrite service** binds to 127.0.0.1 unless a service key is set (a network address without a key refuses to start), its prompt names no real person or dealer (the sign-off is built from the facts), and the Anthropic SDK is pinned with a lockfile.
- Placeholders are neutral, the default role is one constant, the location guard knows the US territories, and `Node >=22` is declared (`.nvmrc`). Settings gained "Forget my synced profile", so the privacy policy's sentence about the synced profile is true; the profile records the website it was saved on, which is what decides whether its dealership part applies elsewhere.
- Tests: 150 unit tests (new `test/manifest.test.js`; new cases for the settings split, the basis choice, the fenced test hook, the price basis and note, the rewrite prompt, the pilot CSV and its lock). `npm run test:e2e` runs the flows one at a time through `scripts/e2e-all.mjs`; `npm run test:e2e:parallel` runs two at a time.
- Documents: README, PILOT.md, the demo script, the sales sheet, the pilot agreement, the privacy policy, the Web Store answers, the subscription agreement and the attorney questions no longer assume one store, one state or one machine; the pilot CSV carries the dealership, website, salesperson and time zone, local times, definitions and totals that add up.
- Not done, needs the owner: asking for the photo host's permission at post time and dropping the static `vehicle-images.carscommerce.inc` host before the Web Store submission (a permission change).

Added
- **Pilot numbers** (`extension/src/pilot.js`, the popup's **Pilot** tab): what the pilot agreement lets Lot Sync record, kept per website in the salesperson's browser. Time per post (from the click on Post to "It's posted", the review included; drafts, skips and abandoned cars recorded as such), which form fields could not be filled per fill attempt (field keys only, never the values or the description), and how long each sold car or price change stayed on the salesperson's listing (from the scan that flagged it to Lot Sync seeing the change on the listing, the person ticking it off, or the website taking it back). The tab shows the medians, the per-field failure table and the open items, and offers **Download CSV** (every post and every item as a row, for the manager), **Copy summary** and **Clear pilot numbers**; "Clear everything for this website" clears them too. The side panel, upkeep, the popup, the wizard and the service worker record; a bookkeeping failure never stops a post.
- **The pilot runbook** (`PILOT.md`): the checklist before the pilot (Milestone 2 live checks, attorney answers, the manager's sign-off, set-up per salesperson), the weekly loop, the log, and the exact definition of each number so the manager can check it.
- **Marketing** (`marketing/`): positioning (internal), the pricing hypothesis in one config (`pricing.json`, quoted by the sales sheet and the positioning and kept equal by a test), the one-page sales sheet, the 10-minute demo script, the pilot offer email and the three onboarding emails. `test/marketing.test.js` keeps the customer-facing copy honest: a person clicks Publish and Lot Sync never does, not affiliated with Meta, no guarantee of account safety, no Meta-approval or partnership wording, no invented statistics, no prices outside the config.
- Tests: 17 new unit tests (137); the post and upkeep e2e flows also check the recorded numbers (not yet run since the change: see HANDOFF.md).

## 0.3.0 (2026-09-27, Milestone 2)

Added
- **Adapters** (`extension/adapters/`): the dealer-platform code lives behind a small interface (detect, scan, normalize, getDetails, makeDirectSearch); `dealerInspire.js` holds today's code and `README.md` lists Dealer.com, DealerOn, Dealer eProcess and DealerFire as TODOs. The page side (`src/scan.js`) is now only a probe plus a per-request call made in the dealer's tab; `src/scanRunner.js` shares the rest between the popup, the wizard and the service worker.
- **Automatic rescans**: every 3 hours while Chrome is open (`chrome.alarms`), the service worker re-reads each known website by calling its inventory search service directly (verified against the live Cars Commerce service), keeping the VIN double-check and the mass-disappearance guard, and puts the salesperson's to-do count on the toolbar badge, with an optional desktop notification when it grows. Needs the host permission the wizard asks for; on by default after granting it, switchable in Settings.
- **First-run wizard** (side panel): read the website, choose the store (pre-ticked from the site name), name and role, the store's address (from the website's structured data), permission for automatic rescans, the posting rules (the same text as `legal/posting-rules.md`, kept in step by a test), then a scan with the final settings. The popup offers it on a website with no settings.
- **Listing upkeep** (`extension/upkeep.js`): each To do item has a button that opens the salesperson's own listing (the link saved when they published, or Marketplace's Your listings page). **Open & update price** waits for the person to click Edit listing, puts the website's new price into the Price box as soon as it appears (and again if the loading form overwrites it), reads it back, and marks the item done when the listing page shows the new price after the person clicks Update. **Open listing** on a sold car waits for the person to click Mark as sold or Delete and marks the item done when the page's static text says so. "I updated it" / "I took it down" close an item by hand. Lot Sync never clicks Update, Mark as sold or Delete, and the unit tests pin that: `upkeep.js` may inject only the price filler and the read-only listing reader, and `facebook/listingSigns.js` (the sold / removed wording, not yet verified live) may describe text only, never a control.
- Manifest: `alarms`, `notifications`, and `optional_host_permissions` for any site (`https://*/*`), requested per dealer website by the wizard.
- Tests: adapters, rescan scheduling and the shared scan runner (unit); a wizard + background-rescan e2e (the service worker rescans with no tab and the badge shows the to-do); an upkeep e2e with mock listing and edit pages, where the test clicks Edit, Update and Mark as sold in place of the person and checks that a listing page with a "Mark as sold" button never reads as sold.

Fixed (after a multi-reviewer pass over Milestone 2, 2026-09-27; 29 confirmed findings, all addressed)
- **Upkeep only acts on this car's listing.** The listing reader now reports whether the page is the car's listing (its id in the address, or its year/make/model on the page), and nothing is filled or ticked off otherwise; the panel says which listing to open. A sold/removed sign counts only when it appears after the page was first read, is looked for in short standalone labels (never in a description that says "sold as-is"), and text in tabs and dialogs is skipped. The mock listing page carries all three traps and the e2e proves the wrong car's edit form is left alone.
- **The background permission is reachable outside the wizard.** Set-up stays offered in the popup until it is finished or skipped ("Not now"), shows "Continue set-up" when it was left half-way (which also hands the wizard a live dealer tab), and Settings has an "Allow automatic rescans" button; ticking the rescan box asks Chrome for the permission from the Save click and the box stays off if it is refused. A schedule that cannot run says so on the To do tab (no permission, or the last automatic rescan failed), and the worker records the failed attempt.
- **The popup no longer writes stale data back.** It follows the diff, snapshot, set-up and site-registry keys in storage (the service worker and the side panel write them while it is open), ignores echoes of its own writes, and keeps the Scan button disabled during a scan.
- **Service worker:** never writes settings, refuses to invent defaults for a website whose settings were cleared, compares the notification with the person's outstanding list rather than the last rescan's count, and measures the 3-hour period from the last attempt with five minutes of slack (a long scan no longer halves the cadence). "Clear everything for this website" also forgets the website for rescans and clears the badge.
- **Wizard:** the final read looks for a live dealer tab, keeps the last good snapshot when a read looks broken (like the popup), writes the site registry alongside the settings so the two agree even if the last read fails, and keeps the notification tick across the permission prompt.
- **Side panel:** a post under way comes back before an unfinished set-up on reopen; a to-do item is refused while a post is under way; starting a post or set-up stops a waiting upkeep, whose late polls can no longer redraw another view; each panel acts only on requests for its own window, the newest one, and never on leftovers older than ten minutes.
- **Guard tests** now catch clicks on any receiver expression and synthesised click events, cover the dealer-site probe and search injections, and check that no guarded file hides a block-comment opener in a string. README no longer says nothing happens in the background (rescans do, with permission; posting never does).
- The end-to-end tests delete their throwaway browser profile and extension copy when they finish (a day of runs had left 1.4 GB behind).

- 124 used and certified cars on the used page, read in one request (about a third of a second); 617 vehicles in all, all 493 new ones skipped.
- 28 at Waynesburg (55 Cranberry, 41 Pleasant Hills); 20 ready to post; 2 need a look (0 miles shown); 7 pre-owned cars have no Carfax link.
- The website's `description` field mixes a pricing disclaimer that repeats on almost every car, raw equipment dumps on cars nobody has written up, and a real paragraph on the rest (6 of 8 sampled). `features` is a clean list. The description writer uses only the paragraph and the features.
- No motorcycle was on the lot, so vehicle-type detection for bikes is a best-effort guess (body type, then bike-only makes).
